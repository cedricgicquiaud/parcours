Les hooks

AVANT CETTE LEÇON Cours Academy : Claude Code in Action

Un hook est une commande que Claude Code exécute lui-même à un moment précis de la session : avant un appel d'outil, après une écriture de fichier, à la fin d'une conversation. Vous ne lui demandez rien — c'est le déclenchement qui est configuré, une fois, dans un fichier de réglages.

La différence avec une instruction écrite dans un prompt est nette : une instruction peut être oubliée ou reformulée, un hook s'exécute toujours. C'est le bon endroit pour ce qui ne doit jamais dépendre de la bonne volonté du modèle : formater le code, refuser une écriture hors du dépôt, journaliser ce qui a été touché.

ASTUCE

Commencez par un hook qui ne fait qu'écrire une ligne dans un fichier de log. Vous verrez l'ordre réel des événements avant d'y brancher quelque chose de bloquant.

À vous

Configurez un hook PreToolUse qui refuse toute écriture en dehors du dossier du projet, et vérifiez qu'il bloque bien une tentative d'écriture dans /tmp.

  • Le hook s'exécute avant l'écriture, pas après
  • Une écriture hors du projet est refusée avec un message lisible
  • Une écriture légitime dans le projet passe sans friction
Indice 1 — La direction
Le hook doit sortir avec un code non nul pour bloquer l'action. Regardez ce que Claude Code passe sur l'entrée standard avant de décider.
Solution
Un script court lit le JSON sur stdin, extrait le chemin cible, le compare au dossier du projet et sort en 2 avec un message si le chemin est ailleurs.
