Une issue est la tâche de GitHub : une fiche qui décrit UN travail à faire, et
un seul. Bien écrite, elle se lit en trente secondes et personne n'a besoin de
poser de question. Cette leçon dissèque le formulaire ; la prochaine vous fera
écrire.

## Le titre : un résultat, pas un thème

Le titre dit ce qui sera vrai quand la tâche sera finie. « Barrer visuellement
les tâches cochées » se vérifie ; « Améliorer l'affichage » ne se vérifie pas —
on ne saura jamais quand c'est fini. Le test : peut-on répondre « c'est fait /
ce n'est pas fait » en lisant le titre seul ?

## La description : trois temps

Une description qui marche raconte toujours la même histoire, dans le même
ordre :

1. **Le problème** — ce qui manque ou ce qui gêne aujourd'hui, en une ou deux
   phrases.
2. **L'action** — ce qu'on décide de faire, sans entrer dans le comment.
3. **« Terminé quand »** — la liste des faits vérifiables qui diront que c'est
   fini, en cases à cocher.

Ce troisième temps devrait vous rappeler quelque chose : ce sont des critères
de réussite, exactement comme ceux que vous cochez dans Parcours. Même idée,
même forme.

## Markdown et l'onglet Preview

La description s'écrit en Markdown — la mise en forme par signes de
ponctuation : `##` devant une ligne en fait un sous-titre, `- [ ]` en début de
ligne dessine une case à cocher. L'onglet **Preview**, en haut de la zone de
texte, montre le rendu final sans quitter le formulaire : écrivez dans
« Write », vérifiez dans « Preview ».

## La colonne de droite

À droite du formulaire, quatre rubriques : **Assignees** (qui s'en occupe),
**Labels** (les étiquettes qui classent), **Milestone** (le jalon qui date) et
**Projects** (le tableau qui affiche). Chacune aura son heure dans les
prochains modules — aujourd'hui on la laisse entièrement vide, et c'est un
choix : une issue vaut d'abord par son texte.

## Constatez-le sur pièce

Le terrain : votre dépôt `todo-app`. Ouvrez son onglet **Issues**, puis le
bouton vert **New issue**. Sans rien créer :

1. Repérez le champ du titre, la zone de description, la colonne de droite et
   ses quatre rubriques.
2. Dans la description, tapez sur une ligne : `- [ ] essai`, puis ouvrez
   l'onglet **Preview** : la ligne est devenue une case à cocher.
3. Quittez le formulaire sans créer l'issue (revenez en arrière ou fermez
   l'onglet) : la création, c'est la prochaine leçon.
